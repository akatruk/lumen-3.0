# Dubbing Implementation Plan

**Goal:** One project button creates an independently downloadable Russian, English or Mandarin voiceover version.
**Architecture:** Separate dubbing rows and durable jobs snapshot the rendered master and transcript. Translation, speech synthesis, audio alignment and muxing operate on this snapshot; project master state is never overwritten.
**Stack:** FastAPI, existing DB adapter/worker, OpenRouter MiniMax TTS, FFmpeg, React.

- [x] Implement backend/dubbing_audio.py: voice catalog, conservative text-to-speech billing reservation, structured translation, transcript-to-master mapping, timing validation and FFmpeg muxing.
- [x] Implement backend/dubbing.py: owned listing/catalog, idempotent sample/full-job submission, immutable snapshot, status/progress, authenticated media/subtitle downloads and worker execution.
- [x] Register schema/router/job handler and interrupted-job cleanup in db.py, app.py and worker.py. Add configured TTS model and price.
- [x] Implement frontend/src/Dubbing.tsx: button and accessible panel, language/voice selectors, short sample audio, explicit replace-audio disclosure, estimated budget, polling, version preview/download and error/retry. Mount near the project player.
- [x] Add focused API/worker/media tests; run relevant existing suites and frontend build. Exercise UI in Chrome with fixtures.
- [x] Deploy only these changed files and built frontend after verifying production drift and idle jobs. Verify Russian sample/full test11 version through actual UI. Record limitations and measured validation results.

Provider references: https://openrouter.ai/docs/guides/overview/multimodal/tts and https://platform.minimax.io/docs/faq/system-voice-id (checked 2026-09-17).

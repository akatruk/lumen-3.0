# ТЗ: готовое видео Lumen с выбранным голосом

Документ описывает только тот путь, который есть в коде Lumen. Другая модель должна повторить его и получить скачанный файл с выбранным голосом. Шаги, которых нет ниже, не добавлять.

Интерфейс ниже дан для языка `ru` (`localStorage` ключ `lumen_language`). Английские идентификаторы, поля API и id голосов скопированы из кода.

Скриншот, который удалось снять: [docs/spec/voice-video/screenshots/01-sign-in.png](screenshots/01-sign-in.png). Это экран входа. Студия, загрузка, голос, музыка, монтаж и скачивание проекта за логином; их кадры в этой папке отсутствуют. Ссылка «Скачать видео» на этом экране скачивает обучающий ролик, а не проект.

## 1. Что обязано быть в готовом файле

Готовый файл — это байты ответа `GET /api/projects/{pid}/media/result`. Кнопка шапки «Скачать видео» (`Download video`) для версии «Готовый ролик» ведёт именно сюда. Плеер и эта кнопка должны открывать одну и ту же выбранную поставку.

В файле одновременно:

- Новая картинка сохранённого монтажа своего исходника `{data_dir}/{pid}/source`. Референс в картинку не входит.
- Выбранная озвучка. Её id — поле `voice` версии `dubbing_versions` (`ru-male`, `ru-female`, `en-male`, `en-female`, `zh-male` или `zh-female`). Дорожка берётся из папки этой версии, а не из звука исходника и не из референса.
- Выбранная музыка, если в монтаже или в финальной поставке есть объект `music` с `asset_id` своего трека `kind=music`. Музыка лежит под голосом (`sidechaincompress`, если `duck` истинно). Если музыки нет, в финале её нет: подставлять трек референса нельзя.
- Длительность совпадает с суммой утверждённых клипов. Расхождение больше допуска (`output_duration_mismatch`) — это провал, а не «почти готово».

Чем готовый файл не является:

- `GET /api/projects/{pid}/media/original` и версия «Исходник» — исходные картинка и звук.
- `GET /api/projects/{pid}/media/master` и версия «Монтаж до озвучки» — картинка рендера со звуком монтажа до озвучки. После рендера с голосом файл `{data_dir}/{pid}/renders/{render_id}/result.mp4` специально заменяется на `original-audio.mp4`. Это не скачиваемый финал.
- Отдельный файл версии в списке «Версии», если `project_final_outputs.version_id` указывает на другую поставку.
- Старый `render_id`, кадр референса, речь референса, «тишина вместо голоса» или предыдущая картинка, подложенная после успешного нового рендера.

Пока озвучка не выбрана, `media/result` отдаёт `renders/{render_id}/result.mp4` со звуком исходника. Это ещё не «видео с выбранным голосом».

Провал рендера, озвучки или сведения музыки не подменяет готовый файл исходником и не откатывает картинку на старый ролик. Предыдущая поставка остаётся, пока `render_audio.publish` или `final_output.select` не записали новую. Успешный ответ задачи и включённая кнопка сами по себе не доказывают, что голос попал в скачанный файл.

## 2. Путь пользователя

Порядок ниже — рабочий. Голос нельзя выбрать до первого готового ролика: без `result.render_id` каталог озвучки возвращает `blocked_reason=dubbing_render_first`.

### 2.1. Войти

Экран: [screenshots/01-sign-in.png](screenshots/01-sign-in.png). Заголовок «Войти» (`Sign in`). Поля «Электронная почта», «Пароль», кнопка «Продолжить». Язык интерфейса — список «Язык интерфейса», значение `ru`.

Этот шаг не выбирает голос ролика. Кнопку входа не нажимать чужими данными и не подменять сессию.

### 2.2. Открыть создание проекта

После входа страница `#studio`, компонент `StudioCreate`. Кнопка библиотеки «Новый проект» (`New project`) тоже ведёт к новому проекту.

Экран создания: «Изучайте приёмы. Рассказывайте свою историю.» Референс нужен всегда: либо 1–5 результатов Douyin, либо файл «Референс-видео». Кнопка «Проанализировать и составить план» (`Analyze & build my plan`) выключена, пока нет своего видео и нет ни одного референса.

Скриншот этой формы не снят: форма за входом.

### 2.3. Референс, не свой ролик

Два законных варианта. Хотя бы один обязателен.

Поиск Douyin. Выбранные карточки уходят в `config.references` как `douyin_results.id` (32 hex), не как `aweme_id`. Запись должна принадлежать пользователю и быть моложе часа. Иначе создание отвечает `422` с `douyin_search_expired` или `invalid_settings`. Повтор одного `aweme_id` — `422` `duplicate_reference`.

Свой файл референса. Поле `type=file` с подписью «Референс-видео» (`Reference video`). Браузер вызывает `holdUpload`: `POST /api/studio/uploads` с `{size, token}`, затем `PUT /api/studio/uploads/{id}?offset=` чанками. Функция возвращает id загрузки. В конфиг своего ролика он попадает как `reference_upload_id`. Вызов `POST /api/studio/uploads/{id}/complete` для этого id запрещён: `complete` создаёт проект, у которого этот файл становится полем `source`.

Пустой список `references: []` без `reference_upload_id` и без файла `reference` — `422` `invalid_settings`. Флажок «Подогнать ритм референса…» (`name=style_match`) сам по себе референс не заменяет.

Файл референса копируется в `{data_dir}/{pid}/reference_source`. В контекст пишется `reference_file: true` и `style_match: true`. В монтаж и в экспорт этот файл не подаётся.

### 2.4. Загрузить своё видео

Поле «Выберите видео для загрузки» (`Choose your video to upload`). Ограничения, которые проверяет сервер: один файл, вертикаль (`height > width`, иначе `422` `owned_vertical`), длительность от 30 до 420 секунд (иначе `422` `owned_duration`), не больше 250 МБ (иначе `413` `upload_too_large`). Невидео — `422` `not_a_video`.

Обязательны «Название проекта» (`title`), «Скрипт и смысл» (`script`), тема `creator.topic` (`real_estate`, `citizenship` или `travel`), «Аудитория» (`audience`), флажок `name=rights`. Без флажка `owned_rights_confirmed` не равен `true`, и схема отвечает `422` `invalid_settings`.

Свой файл грузится через `uploadVideo`, и только он завершается `POST /api/studio/uploads/{id}/complete` с JSON `Create`. Сервер кладёт байты в `{data_dir}/{pid}/source` и ставит задачу `studio_analyze`.

Неверное действие: отправить референс в `file` / `complete`, а свой ролик — в `reference_upload_id`. Тогда голос и картинка будут сняты не с того видео.

### 2.5. Язык на этом экране — язык субтитров, не голос

Список «Язык субтитров» (`Caption language`, поле `language`) принимает только `en` или `zh`. Значения `ru` в `Create.language` нет.

Поле «Голос и стиль» (`Voice & style`, `creator.tone`) — текст тона («спокойно, по делу»). Это не id озвучки. Запись `ru-male` в `tone` голос не выбирает.

`budget` — потолок расходов проекта (`1`, `3`, `5` или `10`), не цена ролика. Озвучка позже резервирует бюджет; при нехватке будет `409` `budget_limit`.

Флажок `style_match` или загруженный референс включает подгонку стиля. Плашка эффектов, если её сохранили на `#look`, уходит как `effect_board`.

### 2.6. Дождаться анализа

Задача `studio_analyze`. Пока `jobs.status` равен `queued` или `running`, правки плана отвечают `409` `job_already_running`.

Анализ читает свой `source`. Референсы Douyin качаются отдельно в `references/{aweme_id}/` и дают DNA. Они не становятся входом рендера. Если включён `style_match`, после плана вызывается сборка монтажа; сбой сборки записывается как неудача подгонки и не подменяет исходник готовым роликом.

Пока нет `result.render_id`, озвучку создать нельзя.

### 2.7. Первый ролик — картинка со звуком исходника

Это ещё не выбранный AI-голос.

Если включена подгонка стиля, кнопка «Утвердить этот ролик» (`Approve this cut`) вызывает `POST /api/studio/projects/{pid}/style-match/approve`. Условия отказа: нет сохранённого монтажа (`422` `save_manual_first`), не все клипы утверждены (`422` `approve_shots_first` или `no_approved_changes`), голос нельзя перенести (`422` и код из `render_audio.summary`). Успех ставит задачу `studio_render` и `stage=render_queued`. Текст кнопки: утверждение рендерит сохранённый монтаж с уже выбранными голосом и музыкой, ничего не публикует и референс не копирует. На первом проходе выбранного голоса ещё нет, поэтому в ролик входит звук своего исходника.

Без подгонки стиля решение по рекомендациям сохраняется `PUT /api/studio/projects/{pid}/plan`, затем «Создать видео с этими изменениями» (`Create video with these changes`) вызывает `POST /api/studio/projects/{pid}/render` с `{revision}`. Нет утверждённых правок — `422` `no_approved_changes`. Чужой `revision` — `409` `plan_changed`.

Кнопка «Проверить правки и создать версию» открывает сводку. «Сохранить и обновить сводку» видео не создаёт. Пока черновик не сохранён, финал не меняется.

Дождаться, пока проект выйдет из `queued` / `rendering`. Провал до `render_audio.publish` оставляет прежний `result`. Новый каталог `renders/{новый render_id}/` при этом не становится скачиваемым финалом.

### 2.8. Выбрать язык озвучки и голос

Экран проекта, вкладка «Монтаж» или блок «Озвучка и язык» (`Voiceover and language`). Панель `Dubbing`, заголовок «Создать озвучку на другом языке» (`Create a translated voiceover`).

Список «Язык озвучки» (`Voiceover language`): `ru` «Русский», `en` «English», `zh` «中文». Это не поле `language` проекта.

Список «AI-голос» (`AI voice`) фильтруется по языку. Id и подписи:

| id | language | Подпись в списке | Поле `voice` в запросе к провайдеру |
| --- | --- | --- | --- |
| `ru-male` | `ru` | Мужской — спокойный | `Russian_ReliableMan` |
| `ru-female` | `ru` | Женский — выразительный | `Russian_BrightHeroine` |
| `en-male` | `en` | Male — gentle | `English_Gentle-voiced_man` |
| `en-female` | `en` | Female — warm | `English_Graceful_Lady` |
| `zh-male` | `zh` | 男声 — 温和 | `Chinese (Mandarin)_Gentleman` |
| `zh-female` | `zh` | 女声 — 亲切 | `Chinese (Mandarin)_Warm_Bestie` |

В интерфейсе начальное значение — `ru` и `ru-male`. В запрос уходит id из первой колонки. Строка провайдера в API студии не передаётся.

«Послушать голос» (`Preview voice`) создаёт `kind=sample`. Это `sample.mp3`, не финал. Неверное действие: считать пробу готовым роликом.

«Создать озвученную версию» (`Create dubbed version`) отправляет:

`POST /api/studio/projects/{pid}/dubbing`

```json
{
  "request_id": "<32 hex>",
  "master_id": "<текущий result.render_id>",
  "language": "ru",
  "voice": "ru-male",
  "kind": "video",
  "replace_audio": true
}
```

`replace_audio` обязан быть `true`. Пара `language` и `voice` из разных строк таблицы — `422` `dubbing_voice_mismatch`. Чужой `master_id` — `409` `master_changed`. Нет ключа провайдера — `503` `provider_not_configured`.

Неверные ожидания, которые сервер отвергает текстом `blocked_reason` или `422`: нет расшифрованной речи (`dubbing_no_speech`), склейка режет фразу (`dubbing_clipped_speech`), фразы наезжают (`dubbing_overlapping_speech`), текст длиннее лимита (`dubbing_transcript_too_long`). Мастер при этом не заменяется.

Когда версия `kind=video` и `status=ready`, сервер сам вызывает `promote_voice` и записывает её в `project_final_outputs`, если `render_id` не сменился. Кнопка «Использовать в финальном видео» (`Use in final video`) делает то же явно: `PUT /api/studio/projects/{pid}/dubbing/final` с `{master_id, version_id}`. «Вернуть звук монтажа до озвучки» (`Use original edit audio`) передаёт `version_id: "master"` и снимает выбранный голос. После этого скачивание снова без AI-голоса.

Статус «Используется в финальном видео» (`Used in final video`) должен относиться к той версии, чей `voice` нужен. Устаревшая версия (`stale: true`, другой `master_id`) в финал не выбирается.

### 2.9. Выбрать музыку

Вкладка «Звук» (`Audio`). Блок «Фоновая музыка» (`Background music`): список «Трек» (`Track`). Пустой пункт — «Без добавленной музыки» (`No added music`). Выбор трека пишет в черновик монтажа `music: {asset_id, source_start: 0, gain_db: -18, fade_in: 1, fade_out: 2, duck: true}`. Это ещё не финальный файл.

Трек — свой ассет `kind=music`, загруженный как материал (`POST /api/studio/uploads/{id}/asset`), не референс и не озвучка. Чужой id — `422` `asset_not_found`. Диапазон вне файла — `422` `invalid_music_range`.

Кнопка «Добавить музыку в финальное видео» (`Add music to final video`) сначала сохраняет монтаж, затем:

`POST /api/studio/projects/{pid}/final-music`

```json
{
  "request_id": "<32 hex>",
  "revision": 1,
  "master_id": "<result.render_id>",
  "final_id": "<текущий final_id, голос или master>"
}
```

Задача называется `final_music`. Она микширует трек поверх текущего голосового файла и не генерирует новый голос. Пока нет готового ролика, кнопка объясняет: «Сначала создайте готовый ролик.» Сбой сведения оставляет прежний финал: «Музыка не обновлена. Прежний финал сохранён.»

Если голос уже выбран, `source_voice` новой строки `final_music_versions` равен id этой озвучки. Смена голоса не стирает выбранный трек: `promote_voice` ставит новую озвучку в очередь сведения с тем же `music`.

### 2.10. Править монтаж

Вкладки: «Монтаж» (`edit`), «Субтитры», «Звук», «Эффекты», «Материалы», «Проверка». Сцены утверждаются по одной. Сохранение монтажа не запускает рендер. Несохранённый черновик не меняет скачиваемый файл.

Повторный рендер после озвучки переносит уже выбранный голос по тем же диапазонам исходника. Новую генерацию голоса для этого не вызывать. Если новый монтаж не покрывает диапазоны озвучки, сводка показывает ошибку, `approve` / `render` отвечают `422`, текущий готовый ролик остаётся.

### 2.11. Утвердить ещё раз, если картинка должна обновиться

Та же кнопка «Утвердить этот ролик» или «Создать видео с этими изменениями». В задачу `studio_render` при подгонке стиля попадает сохранённый монтаж. Если у поставки уже есть голос, в payload добавляется `voice_id` — id выбранной озвучки. Рабочий код рендера берёт голос не из этого поля, а из `project_final_outputs` через `render_audio.snapshot`. Поэтому перед повторным рендером в финале уже должна стоять нужная версия, а не `master`.

`quality_review` у подгонки стиля в этом payload равен `false`.

### 2.12. Дождаться и скачать

Смотреть `projects.status` и задачи проекта. Для озвучки стадии: `queued`, `transcribing`, `translating`, `synthesizing`, `muxing`, затем `ready`. Для музыки: `queued`, `mixing`, затем `ready`. Для картинки: `render_queued`, затем `creating`, `rendering`, `checking`.

Скачивание: в шапке «Скачать видео», когда в плеере выбран «Готовый ролик». Адрес — `GET /api/projects/{pid}/media/result`. Сервер по `project_final_outputs` для текущего `render_id` открывает:

- `audio-mixes/{version_id}/video.mp4`, если поставка `delivery=mix`;
- `dubbing/{version_id}/video.mp4`, если поставка `delivery=dub`;
- иначе `renders/{render_id}/result.mp4`.

Проверка приёмки: скачанные байты совпадают с тем, что играет «Готовый ролик»; в них слышны выбранный голос и, если он выбран, выбранный трек; второй рендер картинки не меняет id голоса; при ошибке рендера предыдущий файл на месте. Ответ `202` или статус задачи `complete` этой проверки не заменяют.

## 3. Что делает сервер после утверждения и после озвучки

### 3.1. Первая картинка

`worker.run_once` берёт задачу `studio_render` и вызывает `studio.render_job`, затем `worker.render_job`. Входы картинки — только `{pid}/source` и свои ассеты. Комментарий рендера: reference files never enter inputs. Речь и музыка референса в экспорт не пишутся. Пробел отчёта стиля `reference_music` прямо говорит, что музыка референса не копируется.

Пока `render_audio.snapshot` не находит голос, `voice_audio` пустой. В `result.mp4` остаётся звук своего монтажа.

### 3.2. Задача `dubbing`

`POST .../dubbing` с `kind=video` вставляет строку `dubbing_versions` (`status=queued`) и ставит задачу с `kind=dubbing` и payload `{id}`.

`dubbing.run_job` для видео:

1. Картинка берётся из `{pid}/renders/{master_id}/result.mp4`. Нет файла — `dubbing_master_missing`, мастер не переписывается.
2. Фразы — `snapshot.phrases` из `mapped_speech` (текст `original`, иначе `en`, иначе `zh`, целые фразы на таймлайне мастера). Если склейка ломает фразу, фразы пустые, и шаг `transcribing` заново слушает мастер, не референс.
3. `translating`: перевод в `Russian`, `English` или `Simplified Mandarin Chinese` через `POST https://openrouter.ai/api/v1/chat/completions`. Модель — `settings.analysis_model`. Выдуманных фраз в промпте нет.
4. `synthesizing`: каждая фраза — `POST https://openrouter.ai/api/v1/audio/speech`. Тело: `model` = `settings.dubbing_model` (по умолчанию `minimax/speech-2.8-hd`), `voice` = строка провайдера из таблицы выше, `input` = текст фразы, `response_format` = `mp3`. Ответ должен быть `audio/*`.
5. Фраза укладывается в свой интервал. Ускорение выше 1.75 — `dubbing_speech_too_long`, мастер не меняется.
6. `muxing`: `assemble` собирает `voice.wav` (тишина и фразы по таймкодам мастера) и пишет `video.mp4`: видео дорожка 0 мастера, аудио дорожка 1 этого wav, `-c:v copy`, AAC 192k, длина мастера.
7. Рядом пишется `subtitles.vtt`.
8. Строка становится `ready`. Если `render_id` всё ещё тот же, `promote_voice` выбирает её финалом. Если к финалу уже привязана музыка, ставится новая задача `final_music` с тем же треком и новым `source_voice`. Голос не заменяется на `master`.

В `finally` задачи озвучки удаляются промежуточные `.wav` и `.mp3`, кроме `sample.mp3`. После первой озвучки в папке остаются `video.mp4` и `subtitles.vtt`. Отдельного `voice.wav` у этой первой версии нет.

Провал ставит версии `status=failed` и не вызывает `select`. Предыдущий финал остаётся. Проект из-за провала `dubbing` не переводится в `failed` целиком.

### 3.3. Задача `final_music`

`final_music.run_job` читает `base_path`: если есть `source_voice`, это `{pid}/dubbing/{source_voice}/video.mp4`. Иначе — `renders/{render_id}/music-free.mp4` или `result.mp4`, но только когда в мастере нет уже вшитой музыки (`409` `music_base_unavailable`).

`music.mix` кладёт трек ассета поверх этой картинки и этого звука, видео копируется (`-c:v copy`). Результат — `{pid}/audio-mixes/{id}/video.mp4`. Выбор в `project_final_outputs` обновляется только если `master_id` и ожидаемый `final_id` не сменились. Иначе версия `failed`, старый финал остаётся.

### 3.4. Второй рендер картинки сохраняет тот же голос

Перед кодированием `worker.render_job` вызывает `render_audio.snapshot`. Для выбранной поставки:

- `delivery=dub`: голос — id этой строки `dubbing_versions`;
- `delivery=mix`: голос — поле `source_voice`, не id микса.

Если в `snapshot` версии есть `carried_voice`, источником считается исходная озвучка (`carried_voice.id`), а не промежуточная копия. Язык и `voice` остаются прежними.

Файл голоса: `{pid}/dubbing/{этот id}/voice.wav`, а если его нет — `video.mp4` в той же папке. Для первой озвучки это `video.mp4`, потому что wav уже удалён. Нет обоих файлов — `selected_audio_unavailable`, рендер падает, старый финал не заменяется.

`render_audio.prepare` режет эту дорожку по таймлайну прошлого мастера и склеивает куски в порядке нового таймлайна. Результат рендера — `{render_folder}/voice-clean.wav`. Дырки в покрытии не добиваются тишиной: нет диапазона — `voiceover_range_unavailable`.

`media.render` получает `voice_audio` и вызывает `replace_picture_audio`: картинка нового монтажа (дорожка `0:v:0`) и `voice-clean.wav` (дорожка `1:a:0`), видео без перекодирования, AAC 192k. Звук исходника в этот файл не возвращается. Затем, если в монтаже есть `music`, `music.mix` добавляет тот же трек поверх уже голосовой дорожки.

`render_audio.publish` копирует поставку отдельно от мастера:

- новый id в `dubbing/{new}/`: `voice.wav` = `voice-clean.wav`, `subtitles.vtt`, `video.mp4` = ролик с голосом без музыки (`music-free.mp4`, если музыка была, иначе `result.mp4`);
- строка `dubbing_versions` с тем же `language` и `voice`, в snapshot поля `carried_from` и `carried_voice`;
- если была музыка — ещё `audio-mixes/{mix}/video.mp4` и `final_music_versions.source_voice` = новый id озвучки;
- `final_output.select` указывает на микс, если он есть, иначе на новую озвучку.

После копирования поставки `original-audio.mp4` заменяет `renders/{render_id}/result.mp4`. Мастер снова со звуком монтажа без перенесённого голоса, чтобы «Вернуть звук монтажа до озвучки» не отдавал AI-голос. Скачивание `media/result` идёт в `dubbing/` или `audio-mixes/`, не в этот `result.mp4`.

Новый синтез `minimax/speech-2.8-hd` на втором рендере картинки не вызывается.

Если исключение случилось до `publish`, `worker` помечает задачу неуспешной и для `studio_render` ставит проекту `status=failed`, не трогая поле `result`. Старый файл остаётся выбранным.

## 4. Жёсткие правила

Не вызывать `complete()` (`POST /api/studio/uploads/{id}/complete`) для загрузки референса. Референс останавливается на `holdUpload` и передаётся как `reference_upload_id` внутри `complete` своего исходника.

Пустой список Douyin без файла референса и без `reference_upload_id` — ошибка. Ответ создания проекта: `422`, деталь `invalid_settings`. Не заменять это выдуманным референсом и не создавать проект без него.

Не подменять готовый файл исходником, `media/original`, `media/master`, `renders/{id}/result.mp4` после голосового рендера и не откатывать скачивание на старый `render_id`, если новый рендер не дошёл до `publish` / `select`. Провал озвучки и сведения музыки тоже не переписывает текущую поставку.

Не впекать в экспорт речь, музыку и кадры референса. В рендер входит `{pid}/source` и свои ассеты. Субтитры и перевод строятся из речи своего мастера. Пробел `reference_music` означает, что музыка референса не копируется.

Выбранный голос остаётся выбранным. Повторный рендер картинки и смена музыки не переключают `voice` на другой id и не возвращают звук исходника, пока пользователь сам не нажмёт «Вернуть звук монтажа до озвучки» (`version_id` = `master`). Id в финале — один из шести: `ru-male`, `ru-female`, `en-male`, `en-female`, `zh-male`, `zh-female`.

Не считать пробу `sample.mp3`, ответ `202`, статус `complete` или включённую кнопку доказательством. Доказательство — скачанный `media/result`.

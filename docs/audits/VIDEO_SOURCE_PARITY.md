# Проверка источников видео: Lumen → lumen-fix

Дата: 2026-09-14. Результат: **функциональная эквивалентность не подтверждена; найдены явные различия**.

База сравнения: локальная копия исходного Lumen, commit 967823e. Исходная VM не проверена из-за отсутствия рабочего SSH-доступа; её фактическая версия и настройки неизвестны. Старый сервер не изменялся.

## Два разных входных потока исходного проекта

1. Исследование трендов: `BACKEND/src/modules/trends-workflow/trends-workflow.processor.ts:49` берёт keyword, platforms, videosPerPlatform, publishTime, method и socialAccountId. API-ветка вызывает TikHub через trendsService; SCRAPE-ветка использует SAU с аккаунтом пользователя. Полученные ссылки передаются в транскрипцию/summary. Это поток исследования референсов; наличие его не означает, что каждый найденный ролик автоматически становится исходником монтажа.
2. Приём исходников монтажа: `BACKEND/src/modules/editing/services/ingestion.service.ts:69` выдаёт подписанный PUT URL в R2 под `raw-videos/{kolProfileId}/...`; confirmUpload валидирует объект, проверяет дубли по ключу и MD5 и создаёт EditingTask. Имеется привязка к KOL и последующее сопоставление со сценарием.

## Правила отбора трендов в API-ветке

`BACKEND/src/modules/trends/trends.service.ts:1059`, fetchFreshVideos:
- платформа и ключевое слово;
- длительность <180 секунд, либо неизвестная;
- дата публикации не старше publishTime дней; неизвестная дата также допускается;
- сортировка по likes по убыванию;
- первые count результатов.

Не переносить эти правила автоматически на SCRAPE-ветку: она обрабатывается отдельно. Другие экраны списка трендов могут использовать собственный score; это не та же сортировка, что в данном workflow.

## Реализация lumen-fix

`backend/app.py:187`: POST /api/projects требует UploadFile. Байты сохраняются в data/{project_id}/source. Нет входа по URL, поисковой платформы, ключевого слова поиска, ранжирования кандидатов, R2/KOL-приёма или MD5-дедупликации. Ограничение длительности допускает ровно 180 секунд, в отличие от строгого <180 в старом отборе трендов.

`backend/worker.py:18`: анализируется загруженный source через уменьшенную копию analysis.mp4. Финальный монтаж читает тот же source. Никакой автоматической замены исходника найденным внешним видео нет. Генерируемые вставки являются отдельным опциональным этапом, а не источником исходного ролика.

## Вывод

Совпадает лишь общий принцип обработки предоставленного видео. Полный путь получения/выбора видео **не совпадает**. Для паритета нужно отдельно восстановить поиск и отбор референсов, связь выбранного материала с проектом, а также определить перенос R2/KOL-приёма, дедупликации и сопоставления со сценарием. Эта проверка не меняла продукт и не запускала внешние поисковые/платные задания.
